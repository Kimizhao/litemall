# 今日营业简报双维度分离与履约日期架构决策

## 背景与痛点
小满食光手作餐品业务存在高频的“提前一天预订、次日制作送达”模式（如夜间预订次日市二早餐、师大送餐）。若营业简报仅按下单/支付时间统计，后厨早晨开工时看板指标显示为零，无法指导当日备料与出餐；若粗暴改为仅按出餐时间统计，则与微信商户平台的每日资金对账单产生冲突，且无法在早晨预知待制作总产值。同时，夜间预订单若直接堆入待制作列表，容易导致后厨打烊前提前误点出餐。

## 架构决策
1. **指标双维度分离（收银 vs 履约）**：
   - **今日履约出餐**（后厨运营口径）：统计 `fulfillment_date = 今日` 的有效订单，展示今日计划出餐单数、出餐总货值及制作完成进度。退款订单完全排除。
   - **今日收银流水**（财务对账口径）：按自然日（00:00~23:59）支付时间 `pay_time` 统计微信实收总额、付款单数与退款金额，严格遵循现金发生制，与微信支付日结对齐。
2. **显式履约日期（Fulfillment Date）与自动化推导**：
   - 订单主表（`litemall_order`）新增 `fulfillment_date`（DATE）字段。
   - 下单时依据时段规则自动计算落库：市二早餐（07:00 后下单即归次日）；师大送餐（16:30 前归当天，之后归次日）；到店自取（优先解析备注，无明确时间以 18:00 为界分界）。
3. **后厨流水视图隔离**：
   - 商家工作台【待制作】流水默认仅加载 `fulfillment_date = 今日` 的订单，清晨自动展现当日任务，晚间完工即清零。
   - 提供 `[今日出餐 | 明日预订]` 子选项卡切换，在明日预订模式下禁用一键出餐，消除误触风险。
4. **即时打票与防漏机制**：
   - 云热敏打印机维持“付款即刻出票”，小票首部加粗打印履约日期与配送时段，保障夜间备料有实体单据依循。
